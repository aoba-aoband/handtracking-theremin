# Regular UI review / 改修方針

2026-10-27。現行コード、一時的なオフライン版の実画面、元の `modular-ui.html` とその確認画像を照合したレビュー。今回は方針の整理であり、製品UIは変更していない。

## 結論

現状は機能を操作部品として並べるところまではできているが、演奏中の視線移動、同時に見たい情報、画面サイズごとの配分が十分に設計されていない。100点を目指す改修では、まずEffectsの配置とウィンドウ操作を直し、次にCamera・Controls・Analysisの役割と表示の優先順位を整える。

小さい文字への変更や、設定項目の削除で解決しない。元サンプルから引き継ぐべき点は、コンパクトな行、整理された見出し、操作と図の近さ、左右の手との対応。サンプルの値、固定配置、仮想計測値は採用しない。

## 確認した問題と根拠

| 問題 | 現行の根拠・影響 |
| --- | --- |
| Effectsが横に長く、縦にも長い | `EffectsPanel` は常に1列の `QVBoxLayout`。1500×950のQtレイアウト測定では各モジュール772px幅、6個の高さ合計2,538px（外側余白を除く）。実デスクトップ上の1000×805の状態では522px幅まで縮むが、モジュールの高さは同じだった。幅を広げても一覧性が改善しない。 |
| エフェクトの操作に到達するまでが長い | Transport、2行の経路説明、Thru、並べ替え説明、最大125pxのリスト、Move Up / Downが常駐。実画面では最初のVibratoも途中までしか見えない。 |
| ON/OFFの位置が揃っていない | `Module` が見出しへ移すのは `*On` と `performanceGate`。共通FXのキーは小文字の `on` のため、本文に独立した横長行ができる。これは好みではなく、配置ルールの不整合。 |
| 上位画面が最低サイズに引っ張られる | Cameraは映像の最低高さ260pxに設定欄245px以上等が加わり、ドックのminimumSizeHintが620px高。狭い状態ではAnalysisが142px高まで圧縮された。 |
| 一部の操作に横スクロールが必要 | Camera Settingsは最低560px幅、Harmonicsは最低780px幅。実画面でPitch Settingsの右側と倍音の右端が切れ、横スクロールが出た。 |
| ウィンドウ機能が発見しにくい | 4パネルは既にfloat/dock可能だが、小さな標準Floatボタンが主な入口。明示的な最前面固定、パネルを戻す一覧、位置のロックがない。 |
| 状態があちこちに分散 | Cameraの状態、ControlsのSC接続、Audio Setup、下部のエラーが離れている。SC language接続とAudio readyの違いを把握しにくい。 |
| 情報の重要度が視覚的に均一 | 保存フォーム、接続説明、演奏ボタン、長い監視値がほぼ同じ重さで並ぶ。Analysisのmonitorは長い文字列の連結で比較しにくい。 |
| 比較したい項目の位置が安定しない | Controlsの一般的なグリッド配置だけでは、Osc 1/2の対や、FilterとFilter Envの関係を保証できない。 |

測定値はQtの論理座標。環境・表示倍率によって実ピクセル数は変わる。実画面では初期状態とEffectsの分離を確認した。今回、演奏中の映像、実測Scope、複数の実モニター、各DPI設定は確認していない。

## 1. Effectsを適正な幅のモジュールとして配置する

### 幅と並べ方

- 1モジュールの目標幅は約380〜440論理px、必要な範囲で480px程度まで。これは初期設計値であり、最大値・負数・長い選択肢・DPIで検証して決める。
- 狭いパネルでは1列、広ければ2〜3列。同じ1枚をパネルいっぱいまで引き伸ばさない。余った幅は他のモジュールを並べるために使う。
- 列数の切り替えでは、左から右、上から下の順序を一定にする。表示の並べ替えで実際のFX順序を変更しない。
- 同じ行のカードを最大高さに強制的に引き伸ばさず、各列の上寄せを基本とする。順序番号と経路表示で処理順を明示する。
- 固定幅の巨大なラベルを避ける。長い説明は補助文・ツールチップへ分けるが、パラメーター名と単位は省略しない。

### モジュール内の構造

```text
Tremolo                       OFF   ⋯
Rate       ─────●─────    5.00  Hz
Depth      ─────●─────   0.500
Wave                    [Sine ▾]
Period                  200.0  ms
[小さなLFOモデル図]
Input [Manual ▾]  Target [Depth ▾]
Key: — · Toggle       [Mapping / Key…]
```

- ON/OFFは全FXで見出し右側に統一。バイパス中も値を読み取り・編集できる。
- 音のパラメーターは常時表示し、「ラベル｜スライダー｜数値｜単位」を揃える。既存の範囲、刻み、対数スケールを維持する。
- LFO図はRate/Depth/Waveに隣接させる。HzとPeriodの両入力は残し、関係を明確にする。
- Input/Target、割り当てキー、現在の入力状態は短い要約を常時表示する。
- 角度の校正、平滑化、反転、キーの編集等は、そのカード内で展開できる詳細領域にまとめる。複数カードを同時に展開可能にし、作業面をタブや排他的な選択画面へ隠さない。展開状態はLayout側で保持する。
- 手入力値と手の角度による現在値を区別する。角度入力時に手動値が上限になることはTargetの近くで短く説明し、SCパラメーターを独自の意味へ言い換えない。

### 経路・並べ替え・Thru

- 常駐の縦長並べ替えリストを、番号付きのコンパクトな経路表示へ置き換える。ドラッグとキーボード操作の両方を用意する。狭い幅では順序を保って折り返す。
- Vibratoは `Source pitch` として別枠に置き、5つの直列FXと混同させない。
- Koala Thruは別の短い入力・出力行として表現し、直列FXの一員に見せない。ON、Level、入力状態を読める状態にする。
- 経路説明を各カードに繰り返さない。詳細説明は必要な場所から参照可能にする。

## 2. 別ウィンドウと最前面固定を明示的に操作できるようにする

Camera / Controls / Effects / Analysisの各見出しに `Detach / Dock`、浮動中は `Always on Top` のピン表示、追加メニューを置く。

| 操作 | 仕様案 |
| --- | --- |
| Detach | 現在のパネルを独立したウィンドウへ。中身・設定値・発音状態は変えない。 |
| Dock | 元の位置、またはユーザーが選んだ領域へ戻す。タブ化を強制しない。 |
| Always on Top | 浮動ウィンドウ単位。初期OFF。固定中はアイコンと文字で明示。アプリ内の前後関係と、他アプリより手前に出す設定を混同しない。 |
| Lock Position | 最前面固定とは別の操作。誤って移動・ドッキングすることを防ぐ。編集操作は維持。 |
| Panels | 全パネルの表示・再表示・Bring to Frontを一覧で操作できる。閉じる操作を導入するなら、この復帰導線も同時に用意。 |
| Recover Windows | モニター取り外し後もタイトルと操作部が画面内へ戻る。矩形の一部が画面に交差するだけでは復帰済みとしない。 |

Layoutには位置・サイズ・ドッキング・表示・最前面固定・詳細の開閉を保存する。Patchには含めない。既存Layoutは新しい属性を省略しても復元できるようにする。

Cameraだけを小さな最前面ウィンドウにし、Controls/Effectsを別モニターで操作できるようにする。一度に全パネルを固定する設計は避ける。最前面ウィンドウがAudio Setupやエラーを覆わないこと、ピン切り替えでキーのHoldが残らないことも確認する。

将来、必要なFXだけを取り出す個別Detachへ拡張できる構造にする。ただし最初の改修では4つの作業パネルの操作を完成させる。多数の小窓を初期状態で生成しない。

## 3. UI全般を整理する

### Camera

- 映像を最優先で伸縮させる。Pitch/Mappingの展開時にも、設定欄の大きな最低高さで他パネルを押しつぶさない。
- 左手の情報と設定は左、右手は右。狭い幅では各側の内部行を折り返す。数値だけを横スクロールの先に追いやらない。
- 左右の検出、Gate、現在のPitch、Octave、Quantizeを読みやすく維持する。映像内の文字を一律に減らさず、ガイド・ランドマーク・状態表示の衝突を避ける。
- 設定を閉じた状態でもRoot/Scale/Min/Max等の短い要約を表示し、演奏条件を確認できるようにする。
- 文字の背景、コントラスト、ガイドのラベル間隔は映像の明暗や拡縮に依存しない。

### Controls

- Probe選択は最上部の近い場所に残す。切り替わる処理経路・利用可能機能を短く表示する。
- BasicのAdditive/Harmonicsをまとまった領域にし、12本を常時横一列で確認できるようにする。
- Harmonicsに必要な幅は実際の値域・小数桁から決める。全Controlsへ最低780pxを伝播させる構造を見直す。それでも全12本が読めない幅では、拡大・Detachの導線を明示する。極端な狭幅で全12本を無理に圧縮して可読性を失わせない。
- Osc 1/2は比較用の一対として扱い、Waveを同じ高さに置く。片方にない操作を架空の有効なパラメーターとして追加しない。
- Filter / Filter Env、Articulation / Envelopeの図と操作を近接配置する。
- 読み取り専用値は入力欄に見せず、ラベル付きの値表示にする。

### Analysis

- 上段はFilter図とPitch / Manual Cutoff / Effective Cutoff等の主要値。名前と値を列で揃える。
- SC monitorの長い連結文を一覧へ変更。詳細テレメトリーやタイミング診断は下段の展開領域へ置く。
- `Measured` / `Model` / `No data` を短い一定の表示にし、図のタイトルを長文にしない。未接続時に値を推定して実測値のように表示しない。
- Scope / FreqScopeは実信号の独立窓を開く現行方式を明示する。アプリ側のピン設定がSCの別プロセスの窓にも適用されるとは扱わない。
- 連続リサイズ時の描画負荷も改善対象。見えない図の更新を抑え、表示整理がOSC送信やカメラ処理を妨げないようにする。

### 共通バー・見た目・状態

- Patch / Layoutは各々「現在名・変更あり表示・Save・Recall」を基本とし、新規名称入力はSave As時に表示する。独立保存を維持する。
- 接続状態は `SC language / Audio / Camera` を分け、停止・準備待ち・実行・異常を文字と状態色で統一する。エラーは短時間で消すだけにせず、復旧操作とログへの導線を添える。
- ドッキング中は共通のStart/Stop/PANICを基本にし、浮動窓には同じ操作を小さく常設する。F5/F6/F12と入力欄保護は維持する。最前面固定とOS全体のグローバルショートカットは別機能であり、後者を勝手に追加しない。
- フォントを縮めず、余白・行高・ラベル幅・数値幅・単位位置を共通ルールにする。数値は桁位置を揃え、操作値と補助説明の強弱を付ける。
- 緑はONや選択、橙は注意/PANICなど意味を限定する。OFFを読めないほど薄くせず、キーボードフォーカスも見えるようにする。

## 改修順と完了基準

| 順番 | 実装範囲 | 完了の判断 |
| --- | --- | --- |
| 1 | Effectsの幅制限・複数列・ON位置・上部圧縮 | 広げると同時に見えるFXが増える。主要な操作の横スクロールがない。音のパラメーターを削除せず、上部の操作だけで表示領域を使い切らない。 |
| 2 | Detach/Dock・ピン・復帰操作・Layout拡張 | Cameraだけを最前面にできる。再起動・Layout呼び出しで復元でき、モニターが減っても操作できる。 |
| 3 | Cameraのサイズ制約、Controlsの比較配置、Analysisの一覧化 | 設定と映像が欠けず、対応する操作と結果を視線の短い移動で確認できる。 |
| 4 | 共通バー、状態表示、文字・余白・キー操作、描画負荷 | 起動できない理由と次の操作が明瞭。通常の入力・演奏キー・浮動窓のフォーカスが衝突しない。 |

検証は単なるスクリーンショット確認で終えない。

- Effects約400 / 800 / 1200px幅を出発点に、1/2/3列とリサイズ境界を確認。表示倍率100 / 125 / 150 / 200%で文字、最大値、単位、選択肢を確認する。
- 1366×768、1920×1080相当、外部モニター配置で検証する。狭い画面で全パネルを同時に大きく表示することは要求せず、縦スクロールと独立窓を使えるようにする。
- 拡縮時はHarmonics12本、Osc比較、Envelope、手の情報とPitch Settingsを重点確認。不可避な最小幅は明示し、黙って右端を欠落させない。
- 両Probeの全設定、角度設定、キー、値域、刻み、単位、対数スケールと双方向同期を照合する。
- ピン、Detach/Dock、Layout切り替えはDSP設定を変更せず、GateやThruを開始させない。発音中のFX順序変更は現行動作を維持する。
- アプリ/浮動窓間のフォーカス移動、数値入力、Holdキー、PANIC、検出喪失、切断を確認する。
- カメラ・OSC・SCの実接続確認と、リサイズ/図の更新を含む性能確認を行う。実機未確認の項目は別記する。

実装上の主な対象は `gui/regular/effects_panel.py`、`widgets.py`、`app.py`。共通のパラメーター定義・状態・OSC/DSPを維持し、UIの配置とウィンドウ管理を分離する。モジュールの有効化キーや表示上の役割は名称の末尾判定だけに頼らず、明示的な定義で扱う。
